# Not needed to build, replay or compare anything. Needed to run the two checkers whose
# whole job is WDL analysis, and to run the offline gate (`make test`) with nothing skipped.
#
#   pip install -r requirements-dev.txt
#
# The gate SKIPS these instead of failing when they are absent, because a contributor
# working only on the Terra side should not need a WDL analyzer to check in.
#
# The last two are NOT imported by any tool in this repo -- yet. They are the imports that two
# review findings had to work around by building a SECOND interpreter, which is the same tax in a
# different costume as a copied version pin: the tools work, the question gets answered by eye, and
# nothing records what was missing. Naming them here is what makes the next one a `pip install`.

miniwdl           # provides both the `miniwdl` CLI used by checks/wdl_gate.sh and the `WDL`
                  # module imported by replay/build_inputs.py. Both name the missing
                  # dependency instead of crashing, so the rest of the repo still runs
                  # without it.

flake8           # `make flake` runs ONLY its pyflakes checks (--select=F): undefined names and
                 # values that are computed then dropped. Not a style checker and never used as
                 # one -- no line length, no whitespace rules, nothing to reformat.
                 # `make setup` does not install this, so `make flake` SKIPs with this file named;
                 # CI installs it, which is where the sweep is actually enforced.

jinja2           # what gatk-sv's own renderer imports (`scripts/inputs/build_inputs.py` over
                 # `inputs/templates/**`). Nothing here imports it, so the plainest question about a
                 # shipped template -- does the single-sample workspace template render, and how many
                 # rows x attributes? -- could not be asked of this venv: `./.venv/bin/python -c
                 # "import jinja2"` was `ModuleNotFoundError: No module named 'jinja2'` (measured in
                 # ./.venv before this line existed), and the review that hit it had to build another
                 # interpreter to render the template it was asking about. Now installed: jinja2 3.1.6.

PyYAML           # provides `yaml`, the difference between parsing `.github/.dockstore.yml` and
                 # text-inspecting it. That file decides which gatk-sv workflows Dockstore publishes,
                 # and it was read with grep only because `./.venv/bin/python -c "import yaml"` was
                 # `ModuleNotFoundError: No module named 'yaml'` (measured the same way). A
                 # `branches:`/`name:` list checked by eye is a check that cannot say how many entries
                 # it saw. Now installed: PyYAML 6.0.3.

#                  (a GitHub release artifact of broadinstitute/womtool, not a package)
#   jq, bcftools, gsutil, gcloud, JDK 17+  - see docs/setup.md
